## 如何新增/维护检查规则

### 规则文件放哪里

- 通用规则文件：`work/quality/quality_standard.md`
- 行业规则文件：建议放在同一目录下，例如：
  - `work/quality/banking_quality_standard.md`
- 运行时可通过参数指定额外规则目录：
  - CLI：`java -jar spec-qc-*.jar scan -req ... --rules /path/to/rules_dir`
  - Web UI：填写“规则目录”

### 行业边界（避免跨行业误扫）

每个 quality 文件开头需要声明适用行业，例如：

```md
### 适用行业
- 适用行业：银行/金融
```

- 通用规则建议写：`适用行业：通用（跨行业）`
- 扫描时可通过环境变量指定当前扫描行业：

```bash
export SPEC_QC_INDUSTRY="银行"
```

行业不匹配的规则文件会被跳过（通用规则始终可用）。

> 安全边界：若规则目录中**仅存在行业专属规则**、却未指定 `SPEC_QC_INDUSTRY`，扫描会明确报错并拒绝加载，避免把某一行业的规则误用到其他行业；请显式指定行业，或为通用规则标注“适用行业：通用”。

### 单条规则建议格式

规则块建议保持统一结构，便于模型稳定命中与输出：

```md
#### 123. 规则标题（尽量写清楚触发条件与问题本质）
- 问题分类：XXX
- 关键词：关键词“A/B/C”
- 问题描述：一句话说明为什么是问题
- 错误问题示例：给 1-2 个典型示例（越具体越好）
- 解决方案：给出可落地的补齐方式（必要时可要求输出表格 suggestion_html）
- 方案收益：可选
- 应用场景：可选（用于约束不要泛化误扫）
- 关联质量标准：精确性/完整性/一致性/可维护性...
```

### 让“建议部分”用表格输出

如果某条规则希望建议以表格形式呈现，建议在规则文本里明确要求，并说明表格列：

- 术语/名词解释：要求输出术语表（术语/定义/口径/示例/备注）
- 权限：要求输出 RBAC 矩阵与数据权限矩阵
- 边界/异常：要求输出边界条件与期望行为清单
- 用户旅程/对象旅程：要求输出旅程矩阵（对象旅程横轴为生命周期）

系统侧也对部分规则做了强制表格输出的约束（见后端提示词约束）。
